## TL;DR

AWS offers two primary load balancers: **Application Load Balancer (ALB)** for HTTP/HTTPS traffic with Layer 7 features, and **Network Load Balancer (NLB)** for TCP/UDP with extreme performance. ALB handles content-based routing, SSL termination, and WebSocket support. NLB delivers millions of requests per second with ultra-low latency. The choice: ALB for web applications, NLB for performance-critical or non-HTTP workloads. Both integrate with Auto Scaling, Route 53, and CloudWatch.

---

## What Is It?

### Application Load Balancer (ALB)

Layer 7 load balancer for HTTP/HTTPS traffic.

![ALB Architecture](/autonomous-researcher/assets/diagrams/alb-architecture.png)

**Features:**
- Path-based routing
- Host-based routing
- SSL termination
- WebSocket support
- HTTP/2

### Network Load Balancer (NLB)

Layer 4 load balancer for TCP/UDP traffic.

![NLB Architecture](/autonomous-researcher/assets/diagrams/nlb-architecture.png)

**Features:**
- Static IP per AZ
- Millions of TPS
- Ultra-low latency (~100μs)
- Preserve client IP
- TCP/UDP support

## Comparison

| Feature | ALB | NLB | Use Case |
|---------|-----|-----|----------|
| **Layer** | 7 (HTTP) | 4 (TCP/UDP) | ALB: Web apps |
| **Latency** | ~400μs | ~100μs | NLB: Real-time |
| **Throughput** | High | Millions RPS | NLB: Scale |
| **Static IP** | No | Yes | NLB: IP whitelisting |
| **SSL** | Terminates | Pass-through | ALB: HTTPS |
| **WebSocket** | Yes | No | ALB: Real-time web |

## Pricing

| Component | ALB | NLB |
|-----------|-----|-----|
| **Per hour** | $0.0225 | $0.0225 |
| **LCU** | $0.008 | $0.006 |
| **~Cost/month** | ~$20-50 | ~$20-40 |

**LCU = Load Balancer Capacity Unit** (connections, processed bytes, rule evaluations)

## GCP Alternative: Cloud Load Balancing

| Feature | AWS ALB/NLB | GCP Cloud LB |
|---------|-------------|--------------|
| **Global LB** | Separate (Global Accelerator) | Native |
| **Pricing** | Per hour + LCU | Per forwarding rule + data |
| **Autoscaling** | Yes | Yes |

**GCP advantage:** Single global load balancer for multi-region.

## Real-World Use Cases

### Use Case 1: Microservices (ALB)

```
ALB
├── /api/v1/users → User Service (ECS)
├── /api/v1/orders → Order Service (ECS)
├── /web/* → Web Frontend (EC2)
└── /assets/* → S3 (static)
```

### Use Case 2: High-Frequency Trading (NLB)

```
Traders → NLB (static IP, low latency)
             ↓
      Trading servers (TCP)
             ↓
      Sub-microsecond response
```

### Use Case 3: Hybrid Web + TCP

```
Internet
    ├── ALB (port 443) → Web tier
    └── NLB (port 3306) → Database access
```

## The Catch

### ALB Limitations

- No static IP (use NLB for that)
- HTTP/HTTPS only
- Higher latency than NLB

### NLB Limitations

- No content-based routing
- No SSL termination (pass-through only)
- Health checks are TCP-level only

---

## Verdict

**ALB Grade: A**
**NLB Grade: A**

**Choose ALB when:**
- HTTP/HTTPS traffic
- Need content routing
- SSL termination required
- WebSocket support needed

**Choose NLB when:**
- TCP/UDP traffic
- Static IP needed
- Extreme performance required
- Preserve client IP
